# Задание: ИИ-система на основе LLM (поэтапно)

Соберите работающую LLM-систему: от промптов и структурированного вывода — к инструментам,
поиску по документам и агентскому циклу. Задание разбито на этапы. Каждый этап — самостоятельный результат, который можно сдать отдельно. 

<!--Не обязательно проходить все этапы: чем больше сделано, тем выше балл.-->

**Цель.** Научиться проектировать, реализовывать и оценивать прикладные LLM-системы: управлять поведением модели промптами, давать ей инструменты, снабжать внешними знаниями и замыкать всё это в агентский цикл. 

Отдельная задача — понять, что из этого посильно моделям 0.5–7b параметров, а что требует больших моделей.

## Общие требования

1. **Воспроизводимость.** Код — в ноутбуке или скриптах + `README` с командами запуска.
   Зафиксируйте версии пакетов и параметры генерации (`temperature`, `top_p`, `seed`).
3. **Не игрушечные инструменты.** Инструмент должен делать реальную работу: читать/писать файлы, выполнять код, обращаться к внешнему API, обращаться к СУБД. Заглушки вида
   «погода в Москве: +5 °C» допустимы только на этапе тестирования.
4. **Измеряйте, а не верьте на слово.** Для каждого этапа — небольшой тест-набор из десятков примеров и значение метрики.


## Этап 0. Тестовый стенд и доступ к LLM

1. Настройте окружение и доступ к LLM. Используйте локальный запуск через ollama, LM Studio и т.п. или используйте облачных провайдеров: GigaChat, proxyapi.ru, ollama, mistral, openrouter и т.п.
   Работа с Ollama из Python — [ollama_python.md](../NLP/LLM_use/ollama_python.md).

Не рекомендуется устанавливать SSL сертификат минцифры глобально. Владелец корневого сертификата, имеет полную техническую власть над зашифрованным трафиком устройства. 


2. Скачайте или проверьте 2-4 LLM.
- Для каждой модели выясните и запишите в таблицу:
  - поддерживает ли она **вызов инструментов** (тег `tools` в библиотеке Ollama);
  - поддерживает ли **режим размышлений** (тег `thinking`);
  - размер контекстного окна;
  - скорость генерации (токенов/с) и потребление памяти;
  - как ведёт себя на русском языке.
- Проверьте, как модель отвечает на один и тот же запрос при `temperature` 0 и 1.
  Воспроизводится ли ответ при `temperature=0`?

## Этап 2. Tool calling


Соберите набор из **4–8 инструментов** выполняющих реальные задачи и научите модель ими пользоваться.

*Примеры* инструментов:

| Инструмент | Что делает по-настоящему |
|---|---|
| `run_python(code)` | выполняет Python в песочнице (вычисления, анализ данных) |
| `query_sql(sql)` | запрос к реальной базе SQLite или другой |
| `read_file` / `write_file` / `list_dir` | работа с настоящей файловой системой |
| `http_get(url)` | реальный HTTP-запрос (например, открытые API без ключа) |
| `search_docs(query)` | поиск по вашей базе документов (пригодится на этапе 3) |
| `calculator(expr)` | безопасные арифметические вычисления |
| `get_datetime()` | текущие дата и время |

1. **Нативный tool calling.** Реализуйте вызов инструментов через `ollama.chat(..., tools=[...])`.
   Разберитесь, как docstring и аннотации типов превращаются в JSON-схему. Смотрите пример
   [tool_calling.py](../../examples/LLM_use/tool_calling.py) и обзор пакета
   [ollama_python.md](../NLP/LLM_use/ollama_python.md).
2. **Тест-набор.** Составьте 20–40 запросов с ожидаемым инструментом и аргументами.
   Считайте: точность выбора инструмента, точность аргументов, долю успешных вызовов.
3. **Сложные случаи.** Проверьте, как система ведёт себя, когда:
   - запрос допускает два инструмента (неоднозначность);
   - нужны **два инструмента подряд** (результат первого — аргумент второго);
   - инструмент вернул ошибку — умеет ли модель исправиться и повторить;
   - запрос вообще не требует инструмента (модель не должна вызывать его «на всякий случай»).
4. **Модели без нативного tool calling?**\
    Реализуйте **ReAct-вариант**: модель пишет
   `Thought / Action / Action Input / Observation` текстом, а вы парсите этот текст.
   Сравните надёжность нативного и текстового подходов на одной и той же модели.
5. **Сколько инструментов способна использовать LLM?**. Оцените пределы LLM по вызову большого количества инструментов.

**Подсказка.** Для маленьких моделей критично ограничивать вывод: используйте `format` со схемой вызова инструмента, короткие описания, примеры в системном промпте. Иногда выгодно разделить роли: маленькая модель выбирает инструмент, а ответ формулирует другая.



## Этап 3. RAG: поиск по своим документам
<!--
Даём системе внешние знания. **RAG по-прежнему актуален** — но причины изменились, и это стоит
понять, а не заучить.

**Почему RAG нужен и в 2026 году**, даже когда у моделей длинный контекст:
- маленькие модели (0.5–7b) имеют контекст всего 4k–32k токенов — без поиска не обойтись;
- «запихнуть» весь корпус в контекст дорого и медленно, а качество падает («lost in the middle»);
- RAG даёт **ссылки на источники** и позволяет **фильтровать по правам доступа**;
- данные обновляются без переобучения модели.

**Задача.** Постройте RAG-систему над реальным корпусом (ваши статьи, документация, база знаний).

1. **Индексация.** Разбейте документы на чанки. Сравните стратегии: фиксированный размер,
   перекрытие, структурные чанки (по заголовкам/абзацам). Как размер чанка влияет на качество?
2. **Эмбеддинги.** Используйте `sentence-transformers` (например `all-MiniLM-L6-v2` — работает
   на CPU). Сравните хотя бы две модели эмбеддингов.
3. **Векторное хранилище.** FAISS или Chroma. Смотрите пример [rag_example.py](../../examples/RAG/rag_example.py).
4. **Поиск.** Сравните:
   - только векторный поиск (dense);
   - только BM25 (разреженный);
   - **гибридный** (BM25 + dense);
   - добавление **reranking** кросс-энкодером.
5. **Метрики поиска.** Соберите 20–30 вопросов с известными правильными фрагментами.
   Считайте recall@k, MRR, NDCG. Покажите, как метрики меняются от стратегии.
6. **Генерация.** Промпт «отвечай только по контексту, ссылайся на источники». Проверьте,
   не галлюцинирует ли модель и приводит ли источники.
7. **Оценка качества ответов.** Разберите RAG-триаду: релевантность контекста, обоснованность
   (groundedness), релевантность ответа. Можно вручную или через RAGAS.

**Результат:** RAG-конвейер + тест-набор + таблица метрик поиска и генерации.
